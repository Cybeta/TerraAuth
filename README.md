# TerraAuth

**Terraria 协议的服务端权威代理 / 反作弊框架**

原版 Terraria 是纯客户端权威架构——位置、血量、伤害全部由客户端上报，服务端只做转发。任何 CE / CheatEngine 用户可以直接写内存改坐标、改血量、改伤害，原版服务器几乎没有拦截能力。

TerraAuth 的目标是在**协议层**把关键状态收回服务端，提供可靠的反作弊能力：客户端只能声明意图，所有状态变更必须经过服务端权威校验后才生效。

## 已实测能力

- ✅ 原版 Terraria 客户端（协议 326）连接 → 握手 → 进入世界 → 正常断开
- ✅ 双客户端同时进服，互相可见（需正确下发包 14 `PlayerActive`）
- ✅ 位置包（包 13）→ 权威校验 → 仿真 → 快照（包 15）经 TCP 下发完整闭环
- ✅ 移动广播：A 发包 13 → B 经 TCP 收到转发，位置一致
- ✅ 移动速度校验：**分轴**判定 —— 水平 `maxSpeed × 60 × Δt + 容差`，垂直 `max(maxSpeed, MaxFallSpeed) × 60 × Δt + 容差`（Δt 钳制在 `[1/60s, 10s]`，不做静默超时无条件放行）
- ✅ 区块流送：包 8 在**游戏内也处理**，并由快照循环按玩家位置补发周边区块（**3×3**，跨区块才发、已发过的区块不重复编码）—— 离开出生点后地形正常
- ✅ 图格推送与原版一致：**少量图格改动**（执行器翻转 / 液体混合）走**包 20（TileSquare）**，**区块级地形**走**包 10（TileSection）**
- ✅ 未建模包边界：未结构化的客户端包默认拒绝，不绕过权威管线即时转发；状态包在仿真提交后由服务端生成同步包
- ✅ Tile（挖 / 放方块）服务端权威全链路：校验 → Command → 仿真 → 增量广播 → SSC 背包扣减
- ✅ 违规处置闭环：窗口内权威拒绝累计达阈值 → 下发包 2 后踢出连接
- ✅ 断线会话保留：断开不销毁运行时，宽限期（`SessionResumeGraceSeconds`，默认 60s）内**同身份重连续回位置 / 血量 / 增益**，出生包下发恢复坐标；连接槽位与并发容量随即释放并复用最小空闲 ID（原版客户端断线即回主菜单，故为「手动重进的会话接管」）
- ✅ 持久化落盘：玩家存档 / 审计 / 封禁写入 SQLite，重启后仍在（封禁不再重启即失效）；**世界改动（挖 / 放 / 液体 / 电线 / 执行器）与箱子内容增量落盘并在启动时回放，玩家建筑与箱子内容重启不丢**
- ✅ 世界文件（`.wld`）：`WorldPath` 指定即可**用真实世界开服**；未指定时按 `WorldSize` **程序化生成三档尺寸**（`Small` 4200×1200 / `Medium` 6400×1800 / `Large` 8400×2400，与原版三档一致），地形为**分层生成**（洞穴 / 矿脉 / 海滩与海水 / 地狱层 / 地下宝箱）；`WorldExportPath` 启用后停机 + 空服导出整份 `.wld`（写出器带写后读回校验 + 原子替换 + `.bak` 滚动）
- ✅ 世界同步与聊天：时间（包 18）/ NPC（包 23）定期下发；聊天（包 82 NetTextModule）可收发，`IServerApi.Broadcast/SendMessage` 真实生效
- ✅ 他人可见性：移动 / 挖放砖 / 受伤 / 增益 / 弹幕 / 掉落物按协议包中继（带玩家字段的包以服务端 ID 覆盖）

## 快速启动

前置：.NET 10 SDK

```bash
cd terraauth
dotnet run --project TerraAuth.csproj -- --config server.json
# 默认监听 127.0.0.1:7777
# Prometheus 指标在 http://127.0.0.1:9090/metrics
```

用原版 Terraria 客户端（协议 326）连接 `127.0.0.1:7777` 即可进入世界。

世界来源由 `server.json` 决定：`WorldPath` 指定 `.wld` 则加载真实世界；为空时按 `WorldSize`（`Small` / `Medium` / `Large`）程序化生成，默认 `Small`。

## SSC 背包权威修复方案

### 现状与风险

SSC 开启时，服务端应是玩家背包的唯一真相。但当前客户端上行的 `InventorySlot`（包 5）在通过槽位、物品 ID 范围和堆叠数量校验后，仍可直接覆盖服务端槽位。攻击者可用内存修改工具将空槽伪造成合法物品 ID（例如 `757` 泰拉刃）并上报；服务端会把该物品当作持有物品。范围外 ID 和超堆叠会被拒绝，但这不能证明物品来源合法。

修复目标是：**客户端只能表达整理背包或使用物品的意图；任何物品的获得、消耗和种类变化必须由服务端可验证事件驱动。**

### P0：停止客户端直接写入

- SSC 开启时，不再将客户端包 5 无条件转换为可覆盖 `PlayerRuntime.Items` 的写入。
- 客户端上报的槽位与服务端权威槽位不一致时，拒绝该上报、记录 `inventory_desync` 审计事件，并重发服务端槽位状态纠正客户端。
- 保留非 SSC 模式的既有客户端背包行为，避免改变该模式的兼容语义。
- 为重复不一致上报接入现有违规窗口和处置策略；正常网络重传不应被误判为凭空造物。

这一步立即封堵“空槽上报为物品 `757`”等凭空生成，但客户端自行移动、合并和拆分物品会暂时被服务端快照还原，直到 P2 完成。

### P1：服务端事件驱动的背包变更

统一由服务端权威入口修改背包，并在提交后持久化及下发槽位同步：

- 服务端存在、距离和归属均已验证的世界掉落物拾取。
- 已打开且有效的箱子会话中的取放与交换。
- 经过服务端校验的放置图格、弹药消耗、药水使用、挖掘和战利品生成。
- 管理员命令、角色档案加载及其他明确受信任的系统操作。

每次变更必须包含来源、输入槽位、输出槽位和数量，保证审计可追溯，且不得依赖客户端随后报告“我已获得某物品”。

### P2：受控背包整理

为拖动、交换、合并、拆分和排序提供服务端事务，而不是直接接受槽位快照：

- 变更前后所有受影响槽位的物品 ID、前缀和总堆叠必须守恒。
- 不允许出现服务端背包中不存在的新物品、前缀或修饰数据。
- 多包组成的一次拖动在短事务窗口内校验，超时、重放或冲突时回滚并下发权威快照。
- 涉及箱子时必须绑定当前玩家会话、箱子索引、会话代数和交互距离。

### P3：持久化、同步与验收

- 玩家登录仅从服务端角色档案恢复 SSC 背包，并完整下发 59 个槽位。
- 权威背包提交后必须同时写入持久化队列并向客户端同步；失败重试不得重复发放物品。
- 增加审计字段：请求来源、拒绝原因、前后槽位摘要和关联世界/箱子/掉落物 ID。
- 自动化覆盖：空槽伪造 `757` 被拒绝并纠正、合法拾取成功、超堆叠和未知 ID 拒绝、槽位交换/拆分守恒、箱子会话越权与重放拒绝、断线重连后的权威背包恢复。

完成 P0-P3 后，CE 仅修改本地内存不会改变服务端背包；伪造的包 5 也无法凭空创建物品。

### 待确认事项：箱子批量操作复制风险

- 原版多人模式已公开报告“快速堆叠到附近箱子”（包 85）与背包排序并发时可复制物品；TerraAuth 当前未实现包 85 入站处理，因此该原版触发链路不能直接进入权威命令管线。
- 但当前包 5（背包槽位）与包 32（箱子槽位）仍接受客户端报告的最终槽位状态，未验证背包、箱子和转移数量在一次操作前后守恒。攻击者可用连续槽位更新模拟全取、全放、整理或重放，风险与原版竞态同类，且可能更直接。
- “仅通过原版界面点击一次全部取出或全部放入，即可稳定复制”尚未在目标协议 326、当前 TerraAuth 构建与真实客户端组合下复现；在完成最小复现和回归测试前，不将其定性为已确认的独立触发漏洞。
- 待验证：双客户端同时操作同一箱子、包 5/32 乱序或重放、关闭/重开箱子边界、断线重连期间的未提交槽位更新，以及高延迟下全取/全放/背包排序组合。
- 修复门槛：所有跨背包与箱子的批量操作必须转为绑定玩家会话、箱子版本和输入槽位版本的服务端原子守恒事务；过期、冲突或不守恒请求必须拒绝，并回发完整权威快照。

## 弹幕类型权威修复方案

### 现状与风险

客户端上行的 `SyncProjectile`（包 27）当前会携带 `ProjectileType`。服务端只校验该类型落在原版有效范围内并执行伤害上界校验，随后以客户端声明的类型登记弹幕。因此，攻击者可将一把原本发射弹幕 `1` 的武器本次发射伪造成合法弹幕 `2`；尽管伤害仍可能受当前手持武器约束，服务端物理、碰撞和后续命中仍会按弹幕 `2` 的能力执行。

修复目标是：**由服务端根据当前权威武器、合法弹药和可验证状态推导本次允许的弹幕类型；客户端不得自由选择弹幕类型。**

### P0：类型与武器绑定校验

- 为已收录原版武器建立“武器 / 合法弹药 / 状态 → 允许弹幕类型集合或生成规则”数据表。
- 包 27 的 `ProjectileType` 不属于当前权威上下文允许集合时，拒绝生成，记录 `projectile_type_mismatch` 审计事件，并纳入违规窗口。
- 空手、已知非发射武器和没有匹配弹药的远程武器不得创建普通攻击弹幕。
- 对尚未收录的武器、Mod 内容和服务端尚不能推导的效果，以显式兼容策略处理；不得静默把它们误判为任意原版弹幕都合法。

### P1：服务端生成弹幕规格

将客户端包 27 从“创建请求”收紧为“使用意图 / 预测确认”：

- 服务端从选中槽位读取权威武器、前缀、弹药、Buff、饰品和冷却状态。
- 服务端计算弹幕类型、数量、伤害、初速度、方向容差、击退和弹药消耗，再创建权威弹幕实体并同步。
- 客户端报告仅可用于关联预测实体；类型、伤害和关键物理能力必须以服务端计算结果覆盖。
- 对多弹、随机弹、弹药转换、特殊武器和前缀，使用受控随机源与规则表生成，而不是允许客户端指定结果。

### P2：发射频率与弹药账本

- 按武器 `useTime` / `useAnimation`、攻击速度修正和当前状态验证最短发射间隔、连发节奏和一次使用可产生的弹幕数量。
- 远程武器仅能消耗服务端背包中匹配 `useAmmo` 的弹药；服务端决定弹药转换后弹幕类型并原子扣除堆叠。
- 拒绝重放、过快发射、缺少弹药、与武器类别不匹配的弹幕和跨槽位切换绕过。
- 发射事务须与 SSC 背包权威方案共用同一提交路径，避免“弹幕已生成、弹药未扣除”或重试重复扣除。

### P3：测试与验收

自动化覆盖至少包括：

- 武器默认弹幕 `1` 伪造为合法类型 `2` 时被拒绝且不登记弹幕。
- 已收录近战、魔法、远程和召唤武器只能生成规则允许的类型。
- 合法弹药、弹药转换、多弹和随机分支的服务端结果可复现。
- 无弹药、越权切换武器、快速重放和伪造额外弹幕均被拒绝。
- 服务端生成的类型、伤害、数量和弹药扣除在断线重连及持久化后保持一致。

完成后，CE 修改客户端发射类型只会影响本地预测；服务端将拒绝不匹配的包，或用自身生成的权威弹幕规格覆盖它。

## 移动权威判定

```
allowedX = MaxSpeed × 60 × Δt + TeleportTolerance
allowedY = max(MaxSpeed, MaxFallSpeed) × 60 × Δt + TeleportTolerance
Δt = ClampDt(now - state.LastSeenAt)   // 钳制 [1/60, 10] 秒
if (|dx| > allowedX || |dy| > allowedY) → Reject("speed_exceeded")，拒绝时不更新权威基准
```

- **分轴判定**：水平用 `MaxSpeed = MaxFlightSpeed = 8.0`（像素/帧）；**垂直用 `max(MaxSpeed, MaxFallSpeed)`**
  （`MaxFallSpeed = 20.0`）。原版下落终速约 20 px/帧，若垂直也按 8 判定，**任何一次正常坠落都会被误判超速**
  → 服务端位置不再更新（后续挖 / 放 / 交互全部 out_of_reach）且累计违规被踢（默认 10 次 / 60 分钟）。
- `TeleportTolerance = 4` 像素；长时静默（>10s）一律按 10s 计（水平上限 `4804px`），**不做无条件放行**（防穿墙 / 瞬移）
- **已知限制**：客户端失焦时位置包间隔可达 4~7s（客户端降频），**水平**静默位移过大仍可能被误判；
  彻底解决需服务端权威移动 / 碰撞校验（Phase 3 世界权威落地后补齐）
